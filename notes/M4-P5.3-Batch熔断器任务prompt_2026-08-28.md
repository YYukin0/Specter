### P5.0 / P5.1 跑出来的、和 P5.3 有关的结论

1. **α（接受率）在这对模型上非常稳定，≈ 0.79**（P1.0 gate 0.7685、P1.3 实测 0.788）。
2. **P5.0 主指标（`mean_emitted_per_round` = `mean(n_accepted)+1` = 每次 target 前向的 token 产出）**：固定 γ∈{1,3,5,7} → 1.77 / 2.80 / 3.49 / 3.67；GammaTune 2.94。**GammaTune 在主指标上没跑赢最优固定 γ**，归因：
   - **坑9**：α 太稳、accept 长度方差不够大，自适应控制器没什么可利用的（GammaTune 论文 Limitations 自己承认）。
   - **坑14（P5.0 新发现，已进 `§9.2`）**：`mean_emitted_per_round` 对 γ **单调非减**（每轮无论浪费多少次 draft 前向，target 接受了前缀就照单全收，指标里没有惩罚 draft 浪费的项），所以固定 γ 越大该指标越高，一个把 γ 控制在中间值的自适应控制器**结构上不可能在这个指标上跑赢大 γ**。**评"要不要投机 / 投机划不划算"这类问题，必须用带 draft 代价的指标（成本模型 `(c+γ)` 或带 KV cache 的墙钟），不能只看每 target 前向的 token 产出。P5.3 直接踩在这个坑的延长线上，见下面"主指标"一节。**
3. **墙钟**：本机 MPS 无 KV cache，`c = T_target/T_draft` 实测只有 ≈ 1.3（被 kernel launch 开销主导，严重低估真实算力比 ~3x）。固定 γ=7 的墙钟加速比已掉到 0.89x（比不投机还慢），γ=1/3 约 1.2x。**墙钟在本地不可靠，只作参考并标 caveat。**

## P5.3 是什么、为什么单独做

依据：`notes/project_plan_v9.md` §7 P5.3（184-186 行）+ §9.2 坑11 / 坑12 + §9.6 风险4 + §13 走读示例（344-346 行）。

**一句话**：GammaTune（P5.0）回答"投机时步长 γ 取多少"；P5.3 回答"高并发 / 高 batch 场景下**要不要**投机"——两个正交的关注点。生产界共识：batch 很大时，target 模型本身已经把 GPU 算力吃满，投机解码省下的"等待 target 单步"的收益消失，反而多出 draft 前向的纯开销（Nightjar 实测高负载下有 30.25% 吞吐倒退，§9.2 坑7）。所以需要一个**熔断器**：检测到高 batch → 自动降级到纯 target 自回归。

**为什么和 P5.0/P5.1 分开、放到这个会话**：P5.3 依赖 batch 维度的信号，而本地没有真实高 batch 吞吐数据（那是 M5[A] "投机解码 batch 吞吐曲线"，云端阶段才有）。所以 P5.3 这次是**机制实现 + 单元测试 + 合成信号驱动的仿真**，真实 batch 曲线联动留到 M5/云端。

**M4 里程碑当前状态**：`TASKS.md` 里 P5.0 / P5.1 已勾，P5.3 未勾，M4 标"部分完成"。这次做完 P5.3 就把 M4 标满。

## 已经确认的决策点（不要重新问用户，直接按这个执行）

1. **模型对**：继续 draft=`Qwen/Qwen2.5-0.5B-Instruct` / target=`Qwen/Qwen2.5-1.5B-Instruct`。不换。
2. **batch 负载信号是合成的，不是实测的**：本地跑不出真实 batch 吞吐，所以熔断器的输入是一个**外部注入的 batch size 轨迹**（一个 `batch_size(step)` 函数或一段离散序列，例如 `[1,1,4,8,32,32,8,1,...]`），不是从真实并发测量。把这一点在结果文件和 commit message 里写清楚："本地用合成 batch 信号驱动，真实 batch 曲线联动是 M5[A]/云端"。
3. **熔断策略用简单阈值，不在本项目 prompt 集上调阈值**（§9.6 风险1：在这次的 prompt 上试出来的阈值，后面再用类似 prompt "验证"熔断器有效，验证的只是过拟合）。给一个 dataclass/config 放阈值（如 `batch_threshold`、`reprobe_every`、`reprobe_gamma`），这次用一组**事先写死的、有明确 rationale 的默认值**（例如 `batch_threshold=8`：低于此用投机、达到此降级；`reprobe_every=50` 步；`reprobe_gamma=3`）。rationale 写在代码注释里。如果默认值在合成信号下行为明显异常，如实记录，不偷偷调。
4. **必须含周期性重探测（坑11）**：Nightjar 批评 DSD"关了就不再收集观测数据、难以重启"。所以熔断器降级后，**每 `reprobe_every` 步强制插一次 `reprobe_gamma` 的小 γ 投机试探**，把这次试探测到的 α / 接受长度**记在 per-task（或 per-prompt）粒度，不是全局一刀切**——§13 走读示例 344-346 行的场景：一批任务 α 下降的真实原因是"任务类型变了"而非"batch 高了"，per-task 记录才能让控制器区分这两种原因。重探测的结果要能驱动"batch 降回来之后重新启用投机解码"的决策。
5. **必须实测切换开销（坑12）**：BanditSpec 被批评"假设切换免费、忽视 KV cache 重建开销"。本项目当前**无 KV cache**，所以有两个选项，任选其一并说清楚：
   - (a) 补一个**最小 KV cache 路径**（只为量化"从投机切回纯 target、或反过来"时重建/丢弃 KV cache 的成本），实测这个开销的 ms 量级。
   - (b) 如果 (a) 工作量过大，退而求其次：量化"切换的浪费性工作"——比如切换时重新 encode 整个前缀的耗时、或一次被丢弃的 draft 前向批次的耗时——作为"切换代价"的代理指标，并明确写"这是代理量，不是真实 KV cache 重建成本"。
   - 参照量级：Nightjar 实测（RTX 4090 + DeepSeek-R1-Distill-Qwen-7B）17.87ms（短输入/小 batch）到 102.03ms（长输入/大 batch）。本机是小模型 + MPS，数字不用对齐，但要能说清自己测的是什么、量级是否合理。
6. **主指标（关键，接坑14）**：判断"熔断有没有用"**不能**用 `mean_emitted_per_round`（对 γ 单调，且它根本不体现"投机 vs 不投机"的开销差异）。用**带 draft 代价的成本模型吞吐**：`throughput = total_emitted_tokens / total_cost_units`，其中每一步的 `cost_units`：
   - 投机轮：`c + γ`（1 次 target 前向折算 `c` + γ 次 draft 前向）
   - 纯 target 降级步：`c`（只 1 次 target 前向，0 次 draft）
   - 复用 `src/verify_gammatune.py` 的 `measure_c()` 拿本机 `c`，并另按文献典型 `c ∈ {4, 7, 10}` 各算一遍（本机实测 c≈1.3 被 launch 开销污染，不代表真实部署）。
   - 次指标：熔断触发/恢复的时间点相对 batch 信号变化的滞后（多少步之后才降级 / 才恢复）、重探测命中率（重探测测到的 α 和当时真实 α 的偏差）、切换总开销占总时间比例。
   - 参考指标：墙钟，**带 caveat**（"本地 MPS 无 KV cache，墙钟不可靠，真实吞吐见 M5[A]/云端"）。
7. **对照组**：在同一条合成 batch 信号 + 同一批 prompt 上，跑三个配置对比：
   - **always-spec**：永远投机解码（固定 γ=3，P1.4 里本设置性价比拐点），不熔断。
   - **always-target**：永远纯 target 自回归，不投机。
   - **circuit-breaker**：P5.3 的熔断器（低 batch 投机、高 batch 降级、周期重探测）。
   - 成功判据：在"低 batch 段占多数 + 有若干高 batch 段"的合成信号下，circuit-breaker 的成本模型吞吐 **≥ max(always-spec, always-target)**（允许 1 个 std 内打平）。如果打不平，如实写现象 + 归因（比如合成信号里高 batch 段太短、切换开销吃掉了收益，正是坑12 要量化的东西）。**不要为了达标改指标口径或调阈值。**
8. **不做的事**：不实现真实多序列 batched 推理（那是 M5[A] / 支柱4，坑3 ragged tensor 那一堆）；不实现 BanditSpec 的 bandit 理论（P5.4 直接克隆其公开代码做基线，坑12）；GammaTune 和熔断器可以正交组合，但这次**不要求**把 GammaTune 塞进熔断器的投机分支（可选：投机分支用固定 γ=3 即可；如果顺手接上 `gammatune_generate` 也行，但别为此纠结）。

- 内存：0.5B+1.5B fp16 双模型加载 ≈ 4-5GB，本机 24GB 够，这类短序列无缓存负载不会失控（和 awq 校准那次撑爆 swap 不是一类）。
