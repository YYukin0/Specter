Specter · engineering study

A local inference-acceleration engine,
built from scratch

Hand-written speculative decoding, a KV-cache-correct serving loop, real int4 on Apple silicon, and a fault-injection oracle stack for testing the decoder itself. Most of it runs on a 24 GB M-series Mac; one benchmark ran on a rented cloud GPU for cross-hardware validation.

How do you know your inference optimization is correct? How do you know it’s actually faster?

Every technique here is implemented from scratch, tested to token-level equivalence with its reference, and reported with its failure cases and null results attached — speculative decoding on this model pair is at parity, not a speedup; the adaptive-γ controller loses to a fixed γ; the circuit breaker trips once in sixteen runs. The value is the verification and measurement discipline.

Engineering notes

Positioning

Where this sits (prior art)

Two established lines this repo draws on and is careful not to reinvent — full citations in the README.

Batch invariance is a kernel-layer property

Thinking Machines’ batch-invariant kernels (He et al., 2025) make the same input give the same bits across batch sizes. Oracle O5 here (note 06) checks batch invariance one layer up — at the decode loop, not the kernel — and holds by construction because the batched decoder shares no ragged tensor.

Mutation testing, applied semantically

cosmic-ray / mutmut mutate syntax (literals, operators). spec_faultlib’s ~20 operators are semantic (crop a KV cache wrong, draw the bonus token from the draft) — a hand-written harness because a literal-mutation engine can’t express those. The methodology — operators → oracle battery → kill matrix — is standard.

Downstream eval over the fake-model gap

The EleutherAI lm-evaluation-harness drives GSM8K + IFEval over an OpenAI-compatible endpoint, so the from-scratch AWQ build is scored on the same config as the baselines (note 07) — not a new harness, just a real one pointed at a from-scratch quantizer.

A textbook roofline case study

Williams et al.’s roofline model plus MLX’s custom-Metal-kernel API. Note 08’s conclusion — mx.compile on a clean op graph beats a single-threadgroup hand kernel — is the expected one; the note is explicit it’s a calibration exercise, not an optimization.

The batched-decoding correctness framing (keep the batch rectangular, or prove output-equivalence per sequence) follows EQSPEC / Batch Speculative Decoding Done Right (arXiv:2510.22876); this repo takes the per-sequence-cache side of that fork (note 03).
